# 求职画像

交付用户能阅读、修改并用于岗位搜索的“画像名称.md”。支持直接描述需求、简历辅助、已有画像修改；不要求提供简历，不把建画像变成长问卷。

## 对话与画像

- 先利用本次要求和已有对话，不重复询问已明确条件。提供简历时读取用户指定文件，用可用的文档工具提取技能、项目、学历与经验；文件无法读取时说明具体缺口，仍可先从已有需求整理草稿。
- 区分简历事实与求职意向：过往行业、现居城市、当前收入不自动变成目标行业、工作地点、期望薪资或硬门槛。背景摘要不保存电话、邮箱、住址、证件号或完整简历。
- 按 [固定格式与命令](references/format.md) 整理属性，优先追问影响岗位方向和筛选结果的缺项或冲突。其他项可推荐默认值。生成完整简表供用户查看，标明推断与默认项；用户确认后保存。用户已授权使用推荐默认值或说“按这个搜索/保存”时，不再加一道确认。
- 普通画像默认：地点不限、发布近2个月或刷新近1个月、薪资门槛0（未设置）、允许面议、排除猎头及雇主不明确、包含相邻方向并要求搜索时标注；行业/游戏不默认排除。明确的用户条件覆盖这些值。Unity非游戏等既有画像可沿用，但不把特定岗位预设套给其他求职方向。
- 排除关键词依据岗位名称和实际职责的语境判断；例如非游戏岗位“游戏引擎经验”不等于游戏开发。福利、工时等偏好默认用于排序，只有用户明确坚持才写为硬条件。

## 工作空间与保存

- 读取宿主当前工作空间/当前工作目录；终端可用 `Get-Location` 或 `pwd`。以用户当前项目为准，不使用插件安装目录。多个工作空间有歧义时询问保存位置；不要全盘扫描简历。
- 根据确认的岗位、方向及必要的城市限定生成简短画像名称，例如“上海Unity非游戏开发”。用户给定名称时优先采用。名称不是新增筛选条件。
- 用脚本创建内部JSON草稿并按对话补充，再调用 `create --workspace <当前工作空间绝对路径>` 生成固定字段的 Markdown。脚本自动处理文件名非法字符；同名依次保存为“名称_2.md”“名称_3.md”，不覆盖原文件。
- 用户要求修改已有画像时，读取指定文件，只修改对应值，保留固定字段和其他内容；不用把修改伪装成新建。用户要求另存时再调用 create。采用UTF-8文件编辑，避免PowerShell默认管道传中文代码。
- Markdown表格为唯一配置来源，不在文件里再藏一份JSON。用户手动修改值后，job-search直接读取这些值。首次生成后用 `check` 快速确认可读取；局部格式错误就局部修正，不重走对话。

## 交付与后续搜索

给出文件链接和一句调用示例：`使用 $job-search，按当前工作空间的“画像名称.md”搜索岗位。`
只有用户要求继续搜索时才交给 job-search；允许用户直接搜索，不强制先走 job-profile。生成画像本身不需要联网，也不代表已经采集了岗位。
