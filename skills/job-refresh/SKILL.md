# 岗位清单复核

逐岗重新检查既有机会，区分仍符合、已关闭/不符和本轮无法核实。招聘日期与本轮复核日期分别记录。

1. 读取 [清单选择与续接约定](../job-search/references/follow-up.md)，按指定文件、对话最近完成清单、工作空间修改时间选择。说明所选文件、当天基准日及默认 60 次 query 上限。已有本入口未完成任务时续接原日期/预算，不切换目标或重开。
2. 使用共享 `report_target.py prepare --mode refresh` 留快照。采用原清单记录的筛选条件或已明确关联的运行画像快照；用户当前明确变更优先，不因同目录画像后来修改而静默换条件。原条件不完整时从对话/报告恢复可确定部分，仅对影响筛选的未知硬条件询问，不要求重新建立画像。
3. 默认复核原主表和有明确招聘链接的待核实候选；旧的明确剔除项仅保留记录，不默认重新扩查。按公司、岗位、地点及招聘链接对应，新增同名岗位或另一城市岗位不能替代原记录。用户明确要求新增机会时再使用 `$job-search`，分开统计新增与原清单变化。
4. 读取 [证据规则](../job-search/references/evidence.md)。先访问原招聘链接，必要时用公司+岗位作定向查询。每岗记录本轮访问/核实日、实际来源和结果。核实职位状态、最新可靠发布日期/刷新日、薪资、雇主和业务方向；学历经验、地点有变化也同步更新。既有福利等详情保留出处，未重查的注明沿用历史资料。
5. 按当天重新计算原画像的自然月时间窗口，包含边界。页面仍显示旧日期就保留旧日期并据此筛选；打开网页、页面底部日期、招聘者在线或转载日不算职位刷新。搜索摘要与正文日期冲突时比较证据，不能机械取最大值。来源没有明确关闭信息时，不以 404、验证码、登录墙或网络失败推断停止招聘。
6. 结果分别处理：本轮取得足够证据且符合条件的进入主表；确认关闭/截止或条件不符的移至变更说明；本轮访问失败或核心证据不足的列待核实，并保留历史值和旧链接。单独写明在招状态未知，不承诺可成功投递。不能只改 as_of、复用旧 kept 就称完成复核，也不为填满表格改变门槛。
7. 原简表与逐岗详情同步更新，主表只计本轮符合条件的记录；在末尾新增变化表：公司/岗位、原值或状态、本轮值或结论、原因、证据链接与核实日期。统计复核总数、仍符合、已关闭/不符、待核实、候选转入，分母一致。保留被移出岗位的历史摘要与原报告，不因数量减少丢失追踪线索。来源全受阻时主表可以为空，准确说明无法完成本轮确认。
8. 按共享约定分批保存、检查并 publish，交付另存文件和变化摘要。条件未变而新日期导致过期时直说时间窗口变化，不解释成公司取消招聘。

详情专项补充使用 `$job-enrich`；长期条件修改使用 `$job-profile`。不自动投递、联系招聘方或建立定时刷新任务。
