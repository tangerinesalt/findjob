# 岗位搜索

交付一份可比较、可追溯的 Markdown 岗位报告，包含简表和逐岗详情。以有效机会为目标，不为本次搜索创建采集工程、不走软件开发流程，不按预定条数凑结果。

## 开始与画像

1. 使用本次明确要求，其次是用户指定画像，最后才是默认值。当前要求足够时直接搜索，不强制经过画像问答。临时覆盖只写本次运行，不修改长期画像。
2. 用宿主可用的搜索、浏览、现有 CLI/API 获取真实网页。先检查能力；只有本地脚本而无实时来源时，说明不能开展新搜索，不能用旧结果冒充新采集。脚本不提供网络搜索服务，也不会安装连接器。
3. 读取 [数据与命令约定](references/data.md)，使用 Python 3.10+ 和 `scripts/job_report.py`。`init --profile` 直接接受 `job-profile` 生成的 Markdown，也兼容旧 JSON；Markdown 固定表格是唯一配置来源。用户未指定文件且要求使用已有画像时，查看当前工作空间根目录，仅有一个有效画像则使用，多个则请用户选择。日期按用户时区当天计算，向 `init` 显式传 `--as-of YYYY-MM-DD`。
4. 内置 [Unity 非游戏画像](references/unity-non-game.json)是可选预设。仅在用户搜索 Unity 且未指定其他画像时使用；其他岗位使用用户条件生成相同格式的画像，不套用 Unity 关键词或薪资线。城市不指定则不限。不确定的硬门槛才需澄清，排序偏好可采用已说明的默认值。
5. 将实际画像、检索基准日、预算上限及是否包含相邻岗位简短告知用户。预设预算 60 个搜索 query，其中最多 12 个用于补充资料；这是上限，不是必须用完的目标。

## 发现 → 核实 → 补充

- 先多来源找岗位链接和基本信息，再核实硬条件，最后只给入选岗位补资料。不要在一条岗位的社保人数、评论或验证码上耗尽预算。
- 需要限定站点时使用半角冒号，如 `site:liepin.com/job/ Unity 数字孪生`；`site.liepin.com` 不是站点限定语法。工具支持 `domains` 时也可直接传域名。查询文本直接传给搜索工具，避免经 shell 拼接改写。
- 一个岗位基本核实建议最多 3 分钟；一次访问失败可换一次可用渠道，再失败则保留缺口并推进。更换渠道只用可访问的公开/已授权来源，不绕过访问控制。来源受阻与搜索无匹配分别记录。
- 读取 [筛选及证据规则](references/evidence.md)。日期、薪资口径、主体和业务方向是核心判断；抓取日、相邻职位、集团其他法人、其他工种的信息不可借用。
- 读取画像全部筛选项：目标岗位、地点及排除地点、招聘类型、工作方式、排除关键词和其他硬条件，由实际职责与证据判断并记录 `profile_match`；排除词指岗位业务，不因公司介绍中偶然提及而剔除。背景和排序偏好不自动变成硬条件。猎头与雇主不明确分别按两个开关处理；日期关系默认“或”，仅显式要求“且”时同时核实发布与刷新日期。
- 每完成一批不超过 5 个岗位就保存短证据和记录；不要等最后回复才落盘。默认只用项目 `.scratch/fingjob/<run-id>/run.json` 作内部续接记录，最终交付仅一份 Markdown。不批量保存网页正文或个人简历。
- 中文记录优先用文件编辑工具写入；需脚本处理时运行 UTF-8 文件，避免通过 Windows PowerShell 默认编码管道传中文代码。具体示例见 [数据与命令约定](references/data.md#中文读写)。
- 主代理在每批搜索前执行 `budget --count N`，再调用网络搜索，将实际每条 query 及结果追加至 `searches`。已预留未使用的额度可以保留，不强行花完。该账本不能拦截宿主工具调用，仍须由执行代理遵守。
- 可以自主判断是否并行；小范围检索默认单代理。只有独立来源检索能缩短总时间时，使用最多 3 个检索子代理。启用时读取 [子代理任务模板](references/worker.md)，由主代理预留总额度、明确各分支配额，只由主代理写运行账本，子代理写自己的小批交接文件。
- 有合格岗位后，按用户要求补职责、要求、福利、每日起止时间/每周天数、加班、参保人数、法律风险、岗位讨论。未知项留空给报告标注，不用猜测填满。单岗缺口不阻塞整份报告。
- 连续两批检索没有新增合格候选且已覆盖至少两个可用来源，或预算耗尽时，停止扩展发现并收尾。所有来源受阻时，明确来源失败；不能推断市场无岗位。用户要求更多覆盖时，可在剩余额度内调整，不隐形突破预算。

## 续接与变更

用户说“继续”时，优先读取当前运行 `run.json` 和已有分支交接，不重新全量检索、不重置额度。检索基准日仍是原运行日。用户要求复核已完成清单时使用 `$job-refresh`；仅补充既有清单详情时使用 `$job-enrich`，两者均支持指定清单或默认选择对话/工作空间最新清单。跨日继续未完成搜索不自动切换入口；明确要求新一轮搜索时建立新运行并重新核实岗位时间。旧报告只能作为线索。画像变化时保留原事实，按新条件重新筛选；旧的 `profile_match` 判断必须重新核对。

## 输出与检查

运行 `check` 查看纳入、剔除、待核实和去重结果。修复结构错误；不能为通过检查伪造证据、改变用户条件或把未知改成“是”。运行 `render` 生成两部分报告，人工抽查对应链接、日期与字段归属。脚本只能校验已输入事实的格式和逻辑，不能证明网页事实真实。

主表只含符合条件的核心岗位；用户允许相邻方向时才收录并明确标记。已暂停、已截止、证据不足的结果不计为合格岗位。最终说明数量、覆盖限制和输出路径，不声称全网穷尽、无风险或已验证所有岗位仍能投递。

不发送消息、不投递、不购买数据。需要建立或修改长期画像时使用 `$job-profile`；直接搜索不必先经过画像入口。
