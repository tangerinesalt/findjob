# 岗位搜索

交付一份附来源的 Markdown 简表和逐岗详情。以有效机会为目标，不凑条数，不为一次搜索创建采集工程。

## 开始

- 条件优先级：本次明确要求 > 指定画像 > 默认值。直接搜索不强制经过画像问答；临时覆盖不改长期画像。需要长期建立/修改时使用 `job-profile`。
- 使用宿主现有搜索、浏览或已授权 CLI/API 获取实时证据。没有在线能力就说明限制，旧清单只作线索；不安装连接器或用旧结果冒充新搜索。
- 用 [数据与命令](references/data.md) 的 init 建立 `.scratch/findjob/<run-id>/run.json`，显式传用户时区基准日。画像支持固定 Markdown 或旧 JSON。要求使用已有画像而未指定时，仅扫描工作空间根目录：一份有效画像就使用，多份才询问。
- 没有指定画像时，用同插件 job-profile 的 draft 命令建立中性条件，再按本次需求填写；不强制经过画像问答或另存长期画像。任何行业预设都须用户明确选用，不能仅凭岗位关键词自动采用。可选示例见 [画像示例](../job-profile/references/example.md)。
- 简短说明本次条件、基准日、相邻方向政策及预算。默认总计最多 60 个 query，其中补充最多 12 个，不要求花完。所有平台默认遵循画像日期窗口；只有用户明确选择额外额度或日期例外时，才按 [平台策略](references/platforms.md) 独立配置。源平台偏好不代表额外预算或放宽日期授权。
- 用户明确指定更小查询上限时，初始化前将它写入本次画像草稿或 init 的 overrides.budget，并相应收小包含在总额内的补充上限；不修改长期画像。仅用 budget 预留几次不等于持久化总上限，不能在续接时恢复成默认60次。

## 采集与记录

- 开始采集前盘点用户点名、当前对话及最近相关搜索/联网验证中的有效线索，按 [线索续接](references/coverage.md) 登记来源和去向；已知直达URL优先打开核实。旧事实只作线索，不等待宽查询偶然再次命中，也不扫描无关画像的全部历史。

- 先发现候选，再核实硬条件，最后补入选岗详情。按 [证据规则](references/evidence.md) 处理画像全部硬条件；背景、偏好不自动变成门槛。核心条件不明列待核实，不能借用抓取日、相邻岗位或其他法人的信息。
- 按 [查询增量参考](references/retrieval.md) 选择下一方向和来源，不设必须遍历的矩阵或来源配额。已有页面一次提取有用字段，只对缺口扩查；同法人资料按适用范围复用。
- 查询直接交给宿主工具，站点限定用半角 `site:域名` 或 domains。中文落盘用 UTF-8 文件编辑；PowerShell 读取指定 UTF8，避免默认管道传中文代码，细节见 data.md。
- 每批搜索前用 budget 按 bucket 预留额度，实际调用逐条写 searches 与 budget_bucket；额外池只供对应域名的发现查询，不能给其他来源或补充扩查加额。页面访问另记 accesses。预留不等于实际调用，脚本不拦截联网。每完成一小批（参考最多 5 岗）按 [小批保存](references/progress.md) 一并保存岗位、调用记录和下一步，不批量保存整页或个人简历。
- 单岗核实约 3 分钟作参考。有价值岗位缺少核心证据时，按 [公开反查](references/retrieval.md#核心证据反查) 查原发布页、官网或其他可对应同岗的公开渠道；仍受阻则记录尝试和缺口，不绕过访问控制。未知福利、工时、社保等不阻塞交付。
- 小任务默认单代理。只有独立来源检索明显节省时间时再读 [子代理模板](references/worker.md)，最多 3 个分支；主代理统一预留总额并写账本，分支各写交接文件。
- 每批按增量和核心缺口调配常规预算。额外池或分支额度用完只结束该批，主代理仍可用general接续该平台、其他来源或公开反查。连续低增量时检查其他路线和未处理的重要线索，再决定全局停止；不设平台或岗位数量下限，预算耗尽即结束扩展。

## 续接与交付

- complete前核对已知线索去向及全局停止理由；未复核、转待核实、证据支持排除分别说明。脚本只检查已登记记录，来源盘点和网页证据仍需审阅；同批事实判定不变不能证明未漏检。

- “继续”先读运行 [进度摘要](references/progress.md) 与已有交接，再读未完成岗位；保留原基准日、画像快照、平台策略和预算，不重新全量检索，旧运行不自动迁移加额。明确新一轮才新建运行。画像变化时保留事实、重新判断匹配，不能沿用旧 profile_match。
- check 查看筛选和去重结果；默认简短输出，排查合并事实时才加 `--full`。脚本稳定合并互补证据并保留冲突，不能证明网页事实真实。不能为通过检查改变用户条件或编造事实。
- render 生成固定两部分报告，抽查链接、日期和字段归属；检查通过后用 progress.md 的 complete 记录最终输出，中间渲染不标完成。主表仅含证据足够且符合条件的岗位；相邻方向须画像允许并标记，LinkedIn 按例外保留的日期与策略单独标明。默认保留岗位核心字段；企业参保、法律风险按需补充。将共性条件和限制集中说明，不重复整段职责或完整查询日志。条件符合与招聘开放状态分开说明；最终给数量、限制和文件链接，不声称全网穷尽或全部仍可投递。
- 已完成清单只补详情用 `job-enrich`，整批核实用 `job-refresh`；跨日续接未完成搜索不自动切换入口。不发送消息、不投递、不购买数据。
