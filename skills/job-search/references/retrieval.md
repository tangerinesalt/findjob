# 以信息增量分配查询

用于新岗位发现或专项补充。以下是选下一次查询的参考，不是必须完成的路线或配额。新搜索的鱼泡、LinkedIn 额外发现池按 [平台策略](platforms.md) 使用：只查对应域名，不转给其他来源或补充任务。

## 找岗位

根据画像先用少量宽查询发现候选，再依据返回结果调整岗位叫法、业务方向与来源。例如财务分析可尝试预算分析、经营分析等相关叫法；前端开发可尝试前端工程师、Web开发等变体。检索变体不是新增硬条件，相邻职责仍单独判断。一次查询通常围绕一个清晰方向；不要把所有技术、地点和福利词堆在同一查询。

发现阶段通常先不加年份或年月，也不把整串检索词都设为精确短语，以免遗漏未被索引展示的岗位日期或不同叫法。需要定向查近期公告或已知岗位时再使用这些限制。日期在候选核实时按画像严格判断，宽查询不意味着放宽筛选。

不同网站反复出现同批职位时，优先换业务方向、岗位叫法或来源类型。官网、高校实名公告、招聘平台具有不同覆盖，按可用性选择；不要求固定数量或遍历全部组合。不要在发现阶段机械使用 `-游戏` 排除词，以免漏掉“游戏引擎经验”等非游戏岗位。

日志可简记 direction（本次方向）、new_jobs（去重后新增候选数）、new_fields（新增且有来源的字段数）；不能把公司参考福利计为本岗已确认福利。不必为每条搜索建立完整矩阵。下一批先看已有结果和明显缺口；缺口本身不会阻止收尾。

连续查询增量很低时，若仍有一个重要方向未触及，可用剩余额度换方向试一次；若无有价值的线索就收尾。对应平台持续访问受限且没有值得尝试的公开渠道时也可提前停止；额外池的 5 次是上限，不要求花完。不要为满足来源数量、覆盖率或预定岗位条数耗完预算。

单路线低增量或分支额度用完不代表全局无增量。下一批同时审视其他来源、相关历史已纳入岗位和本轮高价值缺口；常规池可继续查询鱼泡、LinkedIn。收尾按 [coverage.md](coverage.md) 记录去向和具体停止理由，不能只写“完成预定查询次数”。

## 补资料

先从已有相关页面提取本次范围内的全部可用信息；只对剩余缺口新增查询。按具体缺口选来源：

| 缺口 | 优先线索 |
|---|---|
| 本岗福利 | 原岗位正文；明确适用于该岗位的公司制度 |
| 每日起止、每周天数 | 原岗位正文或适用制度，按工作时间缺口定向查询 |
| 公司统一福利 | 对应公司官方招聘介绍，标明公司口径 |
| 社保人数 | 准确法人名称与年报年份/参保信息，不与“福利、双休”混查 |
| 岗位讨论 | 公司、岗位方向和具体主题；保留时间和个人反馈属性 |

福利、工时、参保人数分别围绕字段查询，不把多个缺口塞进同一检索式。同次任务中，同一法人且适用范围一致的资料可复用；不同子公司、年份、城市制度或其他工种不可直接套用。来源受阻、未搜索、已查未披露分别保留，不能据搜索无增量断言网上没有资料。

## 核心证据反查

优先核实方向明确且有可用渠道的候选，按缺口选路线，不要求走满固定步骤。用公司全名、岗位名、招聘编号、城市和独特职责词定位原发布平台、企业招聘官网/系统、高校实名公告或其他公开同岗详情。已有直接URL先打开；同一失败URL的重复读取不能代替尝试另一个来源。

机构列名与实际用人单位不一致时查原发布来源及两者关系，无法对应仍待核实。公司登记信息可以核对法人，不能证明具体岗位在招。跨平台合并须有招聘编号或法人、职责地点等同岗依据，逐字段保存来源；不用其他职位薪资，也不用另一页“面议”抹掉已知不可比金额。

已有岗位核心补查记general/enrichment，包含在补充上限内；新机会发现记discovery。先补核心缺口，再考虑福利等非阻塞字段，不改phase规避预算。公开渠道受限、无有价值路线或预算不足时，保存实际尝试、缺口及暂缓理由，不能推断岗位不符合或已关闭。

## 成本与恢复

query 数是预算口径；页面访问另记 accesses，不能把“查询不增加、无限打开页面”视为同成本优化。页面必要时只保留相关片段和短事实，不保存整页。

每批取得结果后及时写入日志与事实，再开展下一批。记录方法见 [progress.md](progress.md)，优先用现有 batch 命令一并保存，仍可直接编辑原账本；不需要新增审批。工具调用与本地落盘不是同一事务，中断时仍需结合工具记录补记已执行调用，不能把未落盘当作未执行。

评估改进应区分：新增有效岗位、核心证据补齐、指定字段补齐、query 数、页面访问数和可取得的 token 用量。固定事实的筛选与渲染应稳定；在线检索会受索引、页面状态与查询选择影响，不要求每次结果相同，也不以岗位条数单独证明覆盖改善。
