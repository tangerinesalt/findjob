# findjob 0.2.2 平台规则与验证记录

本次只为鱼泡、LinkedIn 增加发现查询额度，并为 LinkedIn 增加岗位日期例外。基线为 `21f692cdfab3a95c3357c3c87983682ab0eb9cd6`。执行顺序为工作区改造、备份并同步现有 Codex 插件缓存、测试和联网验证；验证通过后才提交推送及从仓库重新安装。没有采用 superpowers 工作流程。

## 改造边界

- 常规画像预算不变，默认 60 次，原补充额度 12 次仍包含其中。鱼泡和 LinkedIn 各最多额外 5 次，仅能用于相应域名的岗位发现查询；默认合计上限为 70。失败与无结果也计数，不强制用满，不能挪给其他平台、官网或补充查询。
- LinkedIn 正文的相对时间保留原文、来源和实际观测日；达到或超过 3 自然月排除，未知日期允许保留但明确标注。跨日复核计算已流逝时间，不伪造绝对发布日期，不无限重用旧的“三天前”。可靠绝对日期和冲突仍参与检查。
- 其他平台沿用画像发布/刷新窗口，鱼泡没有日期例外。关闭状态、截止、业务、薪资、雇主及其他硬条件仍按原规则检查。
- 新搜索默认启用；旧运行不自动迁移，旧报告没有策略时不自动放宽。用户明确所有来源总预算或更严格日期时可关闭本次平台策略。长期画像文件没有改动。
- 报告保存可见策略及机器注释。补充和复核继承已交付报告的日期策略，但两额外发现池上限为 0，不增加这两个流程的查询额度。

完整规则见 [平台策略](../skills/job-search/references/platforms.md)。

## 验证结果

| 验证 | 结果 |
|---|---|
| 改造前基线 | 91 项测试通过 |
| 同步到实际 Codex 安装缓存后 | 147 项测试通过；同步文件逐项 SHA-256 一致 |
| 其他来源规则隔离 | 8 个其他平台域名，5 种日期情形，4 种状态/硬条件变化，共 160 个组合；新旧判定完全一致 |
| 预算与日期边界 | 覆盖池隔离、超额、失败计数、重复批次、伪域名及未限定 OR、三个月边界、中英文相对时间、未知/冲突/关闭、观测跨日与可靠日期优先 |
| 报告后续流程 | 覆盖 Windows 换行、策略继承、策略删除/篡改拦截、旧报告、明确关闭例外及补充/复核无额外额度 |
| 既有观察回放 | 43 个岗位 URL；36 个非 LinkedIn 样本判定不变，2 个 LinkedIn 样本仅解除日期阻塞，鱼泡原有 5 个纳入样本不变 |
| 新联网小样本 | 实际 5 个 query：鱼泡 2、LinkedIn 2、常规智联对照 1；7 次页面访问，5 个岗位 URL；报告交付状态为 complete |
| 联网新旧判定对照 | 相同事实旧规则纳入 2、待核实 3；新规则纳入 4、待核实 1。2 个 LinkedIn 样本显示“1 个月前”“3 周前”及原观测日，3 个非 LinkedIn 样本判定不变 |

回放比较使用相同输入事实分别运行旧策略和新策略，不将本次回放声称为新一轮联网核实。原探索文档的人工分类与脚本输入口径不同，因此这里只比较本次相同事实的新旧结果。

联网验证仅使用公开搜索与直接打开公开详情，没有增加爬虫或绕过访问限制。鱼泡公开移动页面用于补充同岗位 ID 的正文时间；智联对照详情两次打开均超时，仍保留待核实。采集备注使用正向来源描述，避免“非相关推荐”等解释性文字被保守日期排除词误判为推荐岗位证据。

公开网页工具可能返回缓存；纳入表示满足本次有证据支持的筛选规则，不表示已确认实时在招。小样本验证证明查询记账、判定、输出和交付流程可执行，不能据此断言长期召回率提高或所有平台始终可访问。详细账本、岗位来源、缓存备份与测试日志保存在本地忽略目录，个人画像和求职报告不随发布上传。
