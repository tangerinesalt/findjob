# findjob 0.2.1 优化与验证记录

## 范围与执行顺序

保持四个入口、Python 3.10+ 标准库运行依赖和既有 Markdown 格式。本轮先修改工作区，备份并同步实际 Codex/Claude 本地插件缓存，测试通过后才提交、推送，再按 Git 仓库重新安装。没有增加爬虫、来源配额、覆盖矩阵或新的审批流程。

## 实现

1. 薪资：保留明确披露的金额，周期未知继续标未知。脚本只恢复简单金额表达；复杂范围、约数、岗位组年包及浮动组成不猜测。正门槛下不可比较或范围不清的金额进入待核实；两个门槛均为零时提示实际口径。
2. 交付：初始化搜索状态；`run_state.py complete --file --output` 检查格式、当前主表、基准日和筛选条件，记录最终路径及摘要。重复渲染仍是草稿，补充/复核仍由 publish 完成。
3. 保存：`run_state.py batch --file --batch` 一次原子保存岗位、查询、页面访问及短说明。支持批次重试及同 id 部分更新；无效批次不留下半批数据。阶段性候选允许稍后补齐，最终交付再完整检查。补充/复核保持 Markdown 权威。
4. 检索：少量宽查询发现候选，按结果调整叫法、业务和来源；核实阶段严格判断日期。福利、工时、参保人数分别查询；无法取得平台独占信息不阻塞。
5. 报告：合并共性说明，避免相同职责与方向依据复述，精简未披露句，查询过程留在账本。两部分、8列表格、必需详情字段及事实来源保留。
6. 去重：同名跨链接而无已确认身份的机会分别保留并提示疑似关联。不同编号、团队、身份或地点优先分开；已确认同一机会仍合并互补证据与保留冲突。

## 验证边界

固定证据回放验证处理与输出稳定，不能证明在线检索召回率；字符数减少不是端到端计费token节省。开发用基准测试依赖开发环境的包，插件运行仍只依赖标准库。

Codex联网测试遇到子代理额度中断后从已保存账本续接。Claude第一次调用因API余额不足未执行；用户更新配置后，从实际Claude缓存加载四入口并取得官方岗位资料。首轮360秒测试时限结束后，保留材料续接小样本，未重置画像和日期；从实际工具记录补记搜索，额外API列表查询也计入预算。复核再次请求原岗位官方详情，保留未知开放状态及未披露薪资，不把处理日作为刷新日。

Claude续接阶段的CLI报告43轮、约433秒，usage为61,029输入、1,134,464缓存读取、23,401输出token。首轮超时没有完整usage，且没有同条件旧版在线基线；这些是当前宿主/API配置的单次运行报告，不能据此证明端到端token节省或推算实际费用。技能指导也不能保证不同模型每次都按建议选择查询或及时写账本。

通过上述本地检查后发布0.2.1，再从仓库重新安装并核对源码及四入口链路；具体安装记录留在本地临时材料中。
